# Website Deployment Guide

## Overview

The ScheduleGate website (`schedulegate.dev`) is a static HTML site hosted on Vercel. The release pipeline automatically deploys website updates when a new release is created.

## Required GitHub Secrets

The following secrets must be configured in the repository settings (`Settings > Secrets and variables > Actions`):

### Vercel Deployment

| Secret Name | Value | Description |
|-------------|-------|-------------|
| `VERCEL_TOKEN` | *Get from Vercel* | Vercel API token for deployment |
| `VERCEL_ORG_ID` | `team_SVnVnXka9ktKSd4TxChhLsQd` | Vercel team/organization ID |
| `VERCEL_PROJECT_ID` | `prj_7i3AZzH2nzM0ztJx5uGArtd8hGxh` | Vercel project ID for the website |

### Gumroad (local Playwright, not GitHub Secrets)

Set these in your shell before `/release-pipeline`. Never commit them.

| Variable | Description |
|----------|-------------|
| `GUMROAD_EMAIL` | Gumroad login email |
| `GUMROAD_PASSWORD` | Gumroad login password |
| `GUMROAD_PRODUCT_URL` | Optional. Default: `https://junqueira5.gumroad.com/l/schedulegate` |

## Getting a Vercel Token

1. Go to [Vercel Account Settings](https://vercel.com/account/tokens)
2. Click **Create Token**
3. Give it a name (e.g., "GitHub Actions Deployment")
4. Set expiration (recommended: 1 year)
5. Copy the token and add it as `VERCEL_TOKEN` secret

## Manual Deployment

If you need to deploy the website manually:

```bash
cd web/

# Install Vercel CLI (if not already installed)
npm install -g vercel@latest

# Host the user manual at /docs (required before build)
cp ../docs/user-manual.html docs.html

# Pull project configuration
vercel pull --yes

# Build locally (optional)
vercel build

# Deploy to production
vercel deploy --prod
```

## Website Structure

```
web/
├── index.html          # Main landing page (single-page site)
├── terms.html          # Terms of Use (footer-linked)
├── privacy.html        # Privacy Policy (footer-linked)
├── refund.html         # Refund Policy (footer-linked)
├── docs.html           # Copied from docs/user-manual.html at deploy time
├── vercel.json         # Vercel configuration (headers, routing)
├── .vercel/            # Vercel project metadata (tracked in git)
│   ├── project.json    # Project ID and org ID
│   └── output/         # Build output (generated by Vercel)
└── DEPLOYMENT.md       # This file
```

`docs.html` is generated in CI (`cp docs/user-manual.html web/docs.html`) and is not committed (`*.html` is gitignored except `web/index.html`, `web/terms.html`, `web/privacy.html`, and `web/refund.html`). `cleanUrls` serves it at `/docs`.

Legal pages are published (effective 27 August 2026) and linked from the site footer. `cleanUrls` serves them at `/terms`, `/privacy`, and `/refund`.

`/pricing` redirects to `/#pricing` so CLI upgrade links do not 404.

## License Information

- **Community tier**: AGPLv3 (free, 1 assessment/month)

## Updating Website Content

Since the website is a single HTML file, manual edits are required for:

1. **Version updates** - Update terminal demo output, feature descriptions
2. **Pricing changes** - Pro is the only paid CTA. Do not add Team/Lifetime/Enterprise buy links.
3. **License text** - Update footer copyright/license line
4. **Changelog** - Consider adding a `/changelog` page or modal

Future enhancement: Generate website dynamically from release data during CI/CD.

## Troubleshooting

### Deployment fails with "Token expired"
- Generate a new token from Vercel account settings
- Update the `VERCEL_TOKEN` secret in GitHub

### Build fails
- Check `web/index.html` for syntax errors
- Verify Vercel CLI version is up to date: `npm install -g vercel@latest`

### Website not updating after deploy
- Clear browser cache (hard refresh: Cmd+Shift+R / Ctrl+Shift+F5)
- Check Vercel dashboard for deployment status: https://vercel.com/dashboard
